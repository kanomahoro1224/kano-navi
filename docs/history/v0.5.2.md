> [!IMPORTANT]
> **Upgrade notes.** Back up `./data` before pulling the new image, then
> replace `docker-compose.yml` with this release's copy and upgrade with
> `docker compose up -d`; update `KANO_IMAGE` first if it is pinned. The new
> Compose file limits the container to 1 GiB of memory and the Go runtime to
> a 700 MiB soft limit; raise `KANO_MEM_LIMIT` and `GOMEMLIMIT` together in
> `.env` on a larger host. The schedule-image check queue is created
> automatically when an existing database starts; no manual migration is
> needed.

> [!NOTE]
> LINE BLOG thumbnails load the full images until their smaller copies
> exist. Make them once after upgrading from `/admin` → Site → Make missing
> copies, with `docker compose run --rm kano variants`, or install a prepared
> `lineblog-variants.tar` copies archive, as described in
> [LINE BLOG deployments](../development/lineblog-archive.md#deployments).

> [!NOTE]
> The schedule-image check has its own model queue. On the first start after
> upgrading, it takes the image-tagged models of the extraction queue in
> their order, so every image goes to the model that checked it before.
> Reorder or trim it afterwards under `/admin` → LLM. `GET /api/admin/llm`
> adds `verificationQueue`, and `PUT /api/admin/llm/queue` accepts
> `route: "verify"`.

> [!NOTE]
> On the first start after upgrading, detection stage switches saved by an
> earlier release that match neither Detection mode become the nearest mode:
> Everything to the LLM when the message stage runs on all posts, Keyword
> match otherwise. Keyword match can turn on stages that were off. Settings
> with no detection stage running stay as they are. Check `/admin` →
> Detection after upgrading.

> [!WARNING]
> Schedule-image verdicts no longer depend on the check queue, so after
> upgrading the schedule step checks every image without a manual label once
> more, up to 20 images per run. While an image is checked, and after a
> failed or changed verdict, it stays off the board until a check approves it
> again. Label the schedule
> images currently in use under `/admin` → Schedule first if that matters.

Kano Navi v0.5.2 keeps image-heavy pages within a small server's memory by
making smaller image copies ahead of requests, gives the schedule-image check
its own model queue, and keeps extraction results and image verdicts when the
model queues change. The console adds outbound proxies, a timer queue on the
Overview, and Review queue filters with bulk actions.

<details>
<summary><strong>Public pages</strong></summary>

- Opening the LINE BLOG page or the board no longer makes the server resize
  images while visitors wait, so a page full of pictures cannot exhaust a
  small server's memory. A request gets the stored smaller copy or, until one
  exists, the original. Images and their copies are streamed from disk, and
  each file is checked against its hash once instead of on every request.
- The board's first section no longer jumps when the page opens. A return
  visit shows what the device last saw at once and updates it in place, and
  a first visit's placeholder has the ticket's shape.
- About credits 鹿可可, who provides and independently deploys the mainland
  China server site, and links to it. When the operator enables the mirror,
  the Simplified Chinese footer keeps a link to it after its notice is
  dismissed. While the mirror is off, the visitor region response leaves out
  its provider and addresses.
- The Monthly schedule, Post archive and Video archive dialogs put the month
  controls and their switches on the title row when it has room, leaving
  more of the dialog to the month itself.
- The board's post section is titled Recent Posts on X.

</details>

<details>
<summary><strong>Operator console</strong></summary>

- The Overview opens with the queue: the active run, then every timer in the
  order it starts, with when it runs and whether it is due and waiting.
  Start now runs a source's timer at once, or next while another run holds
  the queue, and its next timed run is planned from that run. Run now on the
  Sources page does the same while the source's timer runs.
  `GET /api/admin/overview` adds `queue`, and
  `POST /api/admin/sources/{source}/schedule/start` starts a timer.
- A Proxies page sets up forward proxies for the server's own requests: an
  ordered queue tried one proxy at a time, a choice of which areas use it
  (X, YouTube, Bilibili, media downloads and model providers, each with all
  or selected proxies), an optional direct fallback, and a per-proxy test.
  yt-dlp reads follow the YouTube area, trying up to three proxies.
  Proxy passwords are stored sealed with `LLM_SECRETS_KEY`.
- Console dates read `YYYY-MM-DD` and times `YYYY-MM-DD HH:mm` in Japan
  time, the same in every console language.
- The Review queue's Posts tab filters by step, schedule extraction or
  translation, each with its failure count, and by state within it: failed,
  uncertain or queued for extraction, failed or queued for translation.
  Each row names the step that failed with its error. A failed extraction
  can be dismissed, which stops its retries until the post or the
  extraction queue changes; a failed translation can be
  queued again. Posts can be selected one by one, by shift-click ranges or a page
  at a time, and the selection dismissed, processed again or translated
  again at once. The list pages through every matching post.
- The LLM page has a third queue, Schedule image check, beside extraction
  and translation. It takes only models with the Image tag and never falls
  back to the extraction queue, so a cheap image model can check boards
  while a stronger one reads them. Detection settings show the model each
  of text posts, image posts and the image check calls first.
- Removing a model from a provider's catalog asks for a second click, and
  its icon is shown in the danger color.
- The Schedule page's images open on Active, which leaves out images
  labelled Not a schedule; those move to their own tab.
- A schedule image without dates covers the Monday-to-Sunday weeks of the
  events extracted from its post, so an approved board reaches the board
  and calendar for its week without a manual correction. A corrected period
  still wins.
- The Schedule calendar lists the month's schedule images below the grid,
  and each image card shows Show in calendar, which opens its month.
- Schedule image cards show the source post's time and wording, and Correct
  dates shows the image and the whole post beside the form.
- An X post's dialog on the Posts page can mark one of its images as the
  schedule image, with a reason and optional dates. Synchronization keeps
  the picked image, and the post list shows a Schedule image badge.
- The Review queue, Schedule, Profile and Proxies pages drop their
  explanatory page descriptions.
- The Site page shows how many LINE BLOG, Journey and cached source images
  have their smaller copies, and Make missing copies runs a copies job of up
  to five minutes on the shared queue. The counts validate cached copy files,
  are read when the page opens and after each run, and Check again lists anew.
- A source's manual fetch folds its Last fetch summary from the header,
  leaving the outcome, method and time in view.

</details>

<details>
<summary><strong>Synchronization and extraction</strong></summary>

- The media step makes the smaller copies of newly downloaded images, and of
  older ones that have none, up to 100 images and two minutes per run. It
  reports them as `resized`.
- Changing the extraction queue's models no longer extracts posts again: a
  successful or uncertain result of the post's current input stands
  whichever model produced it, and an emptied queue keeps it. Edited posts,
  failed attempts and reprocess requests still call the queue.
- Changing the schedule-image check queue no longer checks images again: a
  verdict of the current image and source stands whichever model gave it,
  and an emptied queue keeps it. Replaced images and failed checks still
  call the queue.

</details>

<details>
<summary><strong>Runtime and development</strong></summary>

- `kano-go variants` (`npm run variants`) makes the smaller copies of the
  LINE BLOG archive and history images ahead of time. It resumes where it
  stopped and can write to another data directory, so the copies can be made
  on a workstation and copied to the server.
- One core makes the copies for the media step, the command and the
  console's copies run, by group (`lineblog`, `history`, `media`) and within
  optional file and time bounds, and reports each group's originals, ready
  images and copies per width without reading the originals.
- Making copies holds at most two originals in memory at once and scales
  each original once by averaging the area each target pixel covers, which
  needs no buffer larger than the copy; narrower widths are scaled from the
  widest copy, and every copy is written as soon as it is encoded.
- Production Docker Compose limits the container to 1 GiB (`KANO_MEM_LIMIT`)
  and sets the Go runtime's soft limit `GOMEMLIMIT` to 700 MiB.

</details>
