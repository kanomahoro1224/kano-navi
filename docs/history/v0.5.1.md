> [!WARNING]
> **v0.5.0 images cannot make HTTPS requests from the server.** Their runtime
> has no CA certificates, so X, the YouTube Data API and feed, model
> providers and media downloads fail as `*_unavailable` or `*_failed`; only
> yt-dlp still reads. Upgrade every v0.5.0 deployment. Until it runs this
> image, mount the host's CA bundle read-only at
> `/etc/ssl/certs/ca-certificates.crt` in the container.

> [!NOTE]
> **Upgrade notes.** Back up `./data` before pulling the new image, then
> upgrade with `docker compose up -d`; update `KANO_IMAGE` first if it is
> pinned. No settings were added or removed. The additive `assets.manual_image_at`
> column is created automatically when an existing database starts; no manual
> migration is needed. Remove the CA bundle mount if you added one.

Kano Navi v0.5.1 restores outbound HTTPS in the Docker image, so source
reads, schedule extraction, translation and media downloads work again after
v0.5.0.

<details>
<summary><strong>Synchronization and extraction</strong></summary>

- The Docker image carries the system CA certificates again, so source reads,
  model calls and media downloads verify TLS. The production smoke fails an
  image without them.

</details>
